# notifier: как работает и где грабли

Факты проверены владельцем на MacBook Pro (macOS, Claude Desktop 5.1231) 11.11.2026.

## Как ветки получают `notify`

- Claude Desktop подгружает инструменты расширений по требованию (deferred) и **не передаёт веткам `instructions` MCP-сервера**. Без строки в Settings → Your Claude → Instructions модель `notify` не вызывает. Строка — в README, раздел «Claude Desktop: 3 steps».
- Инструмент виден только веткам, **привязанным к компьютеру**: сообщение из Claude Desktop на этом Маке или «+ → Devices» в вебе/на телефоне. Чисто облачные ветки и координатор Projects вызвать `notify` не могут; обход — короткая привязанная ветка.
- Claude Code: плагин с хуками `Stop` и `Notification` (`hooks/hooks.json`) работает без модели. В Cowork/Desktop хуки плагинов не срабатывают (открытые баги Anthropic).

## macOS

- Уведомления идут через `osascript`, macOS приписывает их Script Editor. Доставку подтвердить нельзя, поэтому ответ инструмента — «sent», не «shown».
- Во время записи или трансляции экрана баннеры скрыты и копятся в Центре уведомлений.
- Висеть до закрытия: Script Editor → стиль Alerts (для всех уровней сразу).
- Клик по уведомлению открывает Script Editor, не ветку.
- Python из `~/Documents` macOS не пускает (TCC) — поэтому сервер на Node внутри .mcpb.

## Обновление расширения

- Двойной клик по новому .mcpb иногда показывает только Uninstall: удалить и поставить заново, настройки сбросятся.
- Сервер раз в сутки сверяет версию с GitHub Releases и шлёт уведомление о новой (`~/.claude-smart-notifier.json`).

## Не проверено

- Windows (issue #1), плагин Claude Code в живом Claude Code.
